# 设计：命令参数占位符 + 执行历史

日期：2026-08-21
状态：已实现（自主模式下按本设计直接实施，用户可复查后要求调整）

## 需求

1. **参数占位符**：别名命令中可写占位符，配置时留空、使用时在 TUI 中填入参数值后再执行。
2. **执行历史**：TUI 中展示历史命令及其执行结果，方便复制前序命令的参数值。

## 设计决策

### 占位符语法：`{{名称}}`

选 `{{name}}` 而非 `${name}` / `$1` / `<name>`：

- `${name}`、`$1` 与 shell 变量/位置参数语法冲突——存成 `echo ${HOME}` 的命令本意是让 shell 运行时展开，cm 不应拦截；
- `<name>` 与重定向符号视觉混淆；
- `{{name}}`（Mustache 风格）与 shell 完全无冲突，正则简单：`\{\{\s*([^{}\s]+)\s*\}\}`。

规则：

- 同一参数可出现多次，只提示填写一次，全部替换；
- 参数名不允许空格和花括号；`Alias.Validate` 校验所有 `{{` 必须构成合法占位符（新增/编辑时报错，避免存入坏模板）；
- 替换是纯文本替换，不做任何转义/加引号——用户在预览中看到的就是实际执行的命令（本工具本身就是执行任意命令，这里不是安全边界）。

### 执行入口统一走"解析参数"步骤

所有执行路径（裸 `cm` TUI 执行、`cm run`、`--pick`/`--print` 供 shell eval）在执行前检查占位符：

- 无占位符 → 行为与现在完全一致；
- 有占位符且 stdin 是 TTY → 打开参数填写 TUI（`internal/prompt`），取消则回到 picker；
- 有占位符且非交互 → 明确报错（提示需要终端）。

### 参数填写 TUI（internal/prompt）

```
 cm · 执行 ssh-srv

 参数（enter 下一项/运行 · ↑↓ 切换 · tab 复制历史参数 · esc 取消）
   host  [192.168.1.10]
   user  [root        ]

 运行命令:
 ╭─────────────────────────╮
 │ ssh root@192.168.1.10   │
 ╰─────────────────────────╯

 最近执行（tab 填入）:
   ▸ 2 小时前  ssh root@192.168.1.10   ✓ 3s
     3 天前    ssh root@192.168.1.20   ✗
```

- 输入值**默认预填该别名最近一次**的参数值（重复上次执行 = 连按 enter）；
- **tab 在历史记录间循环**，选中即把该次的全部参数填入输入框——"复制前序命令的参数"的一键路径；输入任意字符取消高亮；
- 底部实时预览替换后的完整命令；
- enter 在最后一项上确认并运行；esc 取消。

### 执行历史（internal/history）

- 存储：配置目录下 `history.json`（`platform.HistoryPath`），0600 权限、临时文件 + rename 原子写（与 aliases.json 同一套模式）；
- 记录字段：`alias`、`template`（含占位符原命令）、`command`（替换后实际命令）、`params`（名称→值）、`exit_code`（`*int`，nil 表示 shell eval 模式下结果未知）、`started_at`、`duration_ms`；
- 上限 500 条，超出自动淘汰最旧；
- **所有执行都记录**（含无参数命令），这样历史才是完整的"执行过什么"；
- 历史是附属功能：打开/写入失败只提示不阻塞执行（nil store 安全）。

**不捕获命令 stdout/stderr**：runner 目前 stdio 直通终端，若插入管道捕获输出会破坏 ssh 等**交互式命令**（pty 直连是这类工具的主场景）。"执行结果"以退出码 + 耗时呈现；参数值在 `command`/`params` 中完整可见，已满足"复制参数"诉求。

### 展示位置

1. **参数表单**底部：该别名最近 5 条（见上图），tab 一键填入；
2. **picker 预览面板**：新增"最近执行"块，最多 3 条（状态 + 相对时间 + 替换后命令）；
3. **`cm history [别名] [-n 20]`** 子命令：表格查看全部历史（非交互查询）。

### shell 集成（--pick/--print）模式

参数 TUI 渲染到 stderr（stdout 留给被 eval 的命令），流程不变：填参 → 打印替换后命令 → 当前 shell eval。此模式下 cm 无法得知 eval 结果，历史记录 exit_code 为 nil（展示为 "—"）。

## 追加决策：参数表单内联渲染（2026-08-21 第二轮）

问题：altscreen TUI 覆盖整个终端，用户在当前 session 里上一个**非 cm** 命令的
输出（常是参数值的来源，如刚查到的 pod 名 / IP）看不到了；而子进程没有任何
API 能读回终端滚回内容，输出只能"让用户看到"，不能"程序读到"。

方案：参数表单（internal/prompt）改为**内联渲染**（去掉 `tea.WithAltScreen()`，
View 不再 `lipgloss.Place` 居中撑满）。时序上主选择器先退出 altscreen——终端
自动还原之前的输出——随后表单只在光标处渲染小框。这样上一个命令的输出保持
可见，用户鼠标复制 + 终端粘贴键即可填入参数。主选择器 / add 表单保持
altscreen（全屏双栏布局，且退出即还原，不影响上述时序）。

明确不做（暂缓）：通过 shell 集成 precmd 钩子把上一条命令行写入文件、在表单中
展示——只能拿到命令行拿不到输出，且需用户重装集成；若后续需要再加。

## 追加决策：参数说明内联在占位符中（2026-08-21 第三轮）

需求：每个参数可添加说明，使用时展示。方案：占位符语法扩展为
`{{名称:说明}}`（说明可选，可含空格与冒号、不可含花括号；名称不可含冒号）。

选择内联而非在 Alias 上加 ParamDescs 字段：说明跟着命令字符串走——存储零
改动，非交互 `cm add`、手改 JSON、复制别名都能携带；代价是命令模板稍长。
同名占位符多次出现时以首次的说明为准；`{{名称:}}` 视为无说明。

展示位置：参数表单中说明渲染在对应输入框下方（`└ 说明`，与输入内容对齐）；
add/edit 表单识别到参数时列出 `名称（说明）`；写法提示行更新为
`支持参数: {{名称:说明}} 执行时填 · 例: …`。历史记录的 params 仍按名称
存值，不受影响。

## 明确不做（YAGNI）

- 不捕获命令输出（破坏交互式命令）；
- 不做参数默认值语法 `{{a=xxx}}`（历史预填已覆盖）；
- shell 集成脚本不回传 eval 退出码（增加耦合，价值低）；
- 不做历史编辑/清理命令（自动淘汰 500 条；文件是可读 JSON 可手删）。
