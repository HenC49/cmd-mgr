# 设计：别名导入导出（cm export / cm import）

日期：2026-09-04
状态：已实现（自主模式下按本设计直接实施，用户可复查后要求调整）

## 需求

已有别名配置支持导入导出：备份、换机迁移、团队共享。

## 设计决策

### 导出格式 = aliases.json 同构 JSON

`cm export` 输出 `{"version":1,"aliases":[...]}`，与库文件完全同构：

- 导出文件可直接放回存储位置当备份恢复，零转换；
- 保留全部字段（标签、创建时间、使用统计），迁移后排序/统计不丢；
- 执行历史不导出——历史是本机行为记录，跨机共享无意义且含执行痕迹
  （密钥值虽已脱敏，仍是"执行过什么"的隐私面）。

`cm export [文件]`：缺省输出到 stdout（unix 管道友好），指定文件则写入（0600）。

### 导入：合并而非替换 + 逐条校验

`cm import <文件|->`（`-` 读 stdin，支持 `cm export | ssh srv 'cm import -'`）：

- 接受导出格式与纯数组 `[...]` 两种形状（手写/裁剪过的文件也能用）；
- **合并语义**：重名默认跳过（保留本地版本，安全默认）；`--overwrite` 覆盖；
- 逐条跑 `Alias.Validate`（含占位符/密钥引用语法），坏条目跳过并逐条报告，
  不让一条坏数据挡住整个导入；`null` 条目、空别名同样归入无效报告；
- 文件内重名后者胜出（一次去重，行为确定）；
- `--dry-run` 只计算结果不落盘——预览 `--overwrite` 会改什么。

### 落盘与原子性

导入在别名列表**副本**上合并，全部条目处理完后一次性替换内存数据并走既有的
`Save()`（临时文件 + rename 原子写）。dry-run 直接不替换——内存与磁盘都不受影响。

### 字段保留策略

导入条目原样保留文件中的创建时间与使用统计（迁移保真）；创建时间为零
（手写文件没写）补当前时间。别名两侧空白修剪后入库。

## 追加决策：主选择器（TUI）里的导入导出入口（2026-09-04 第二轮）

需求：不离开 TUI 也能导出/导入。方案：picker 新增两个动作键——
`ctrl+x` 导出、`ctrl+o` 导入（动作键全部 ctrl 组合，与既有约定一致，
不占用打字即过滤的字符键）。picker 只负责返回 `ActionExport/ActionImport`，
具体流程由外层（root.go 主循环）执行，与新增/编辑同一套模式。

流程复用新建的 `internal/input` 轻量 TUI（内联渲染，同 prompt）：

- **Run**：单字段输入表单（Title/Label/Default/Placeholder/Validate）。
  导出预填 `~/cm-aliases-YYYYMMDD.json`（enter 即写，路径校验：非空 +
  父目录存在）；导入 enter 时即校验文件可读且格式可解析（错误展示在
  表单内，改了再按 enter，不用重来）。`~` 前缀按家目录展开。
- **Show**：只读结果框（enter 返回）。导入导出的结果/错误都用它展示——
  picker 重进 altscreen 后普通输出会被切走，结果框保证用户看得见反馈。

TUI 导入固定"重名跳过"语义（与 CLI 默认一致）；结果框在有跳过时提示
`cm import --overwrite <文件>` 的覆盖途径。导入后回到 picker，
下一轮循环 `st.List()` 自然刷新列表。

footer 帮助改为两行（动作键 7 个，一行 80 列放不下），列表区高度相应 -1；
空库提示增加"按 ctrl+o 从文件导入"（首次使用者的关键路径）。

## 已验证

- 单元测试：合并（跳过/覆盖/无效/null/修剪）、文件内去重、dry-run 不落盘、
  覆盖落盘重开可见、导出→导入往返一致（含密钥占位符命令）、两种输入格式解析、
  坏 JSON 报错、报告折叠；
- 真实二进制 E2E：导出文件与 stdout、空库导入还原、重名跳过、dry-run+overwrite
  预览（库未变）、真正覆盖、`cm export | cm import -` 管道迁移、纯数组+坏条目报告；
- TUI E2E（pty 按真实按键时序驱动）：ctrl+x 导出（默认路径落盘 0600、
  结果框展示条数）→ ctrl+o 导入新文件（"新增 1"、列表刷新为 3 条）→ esc 退出。

## 明确不做（YAGNI）

- 不做交互式逐条冲突确认（flags 覆盖脚本与人工两类场景，行为可预期）；
- 不做选择性导出（按标签/别名过滤）——`cm export` 输出的是 JSON，jq 即可裁剪，
  且纯数组格式导入已被支持；
- 不导出执行历史；
- 不做 YAML/CSV 等其他格式。
